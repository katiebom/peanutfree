# 주간 업데이트 파이프라인

```
Gemini (월 09:00)   시트에 행 추가 ('후보' 탭 또는 '4단계_안심분류_DB') + 출처 URL / 원문 인용 / 출처 유형
Mac (월 10:00)      scripts/weekly-import.sh → 가져오기 + 기계 검증 + Claude 확인 대기 목록 (장부 기준으로 새·변경 행만 처리)
Claude 확인         🟢·🔴 통과분만: node scripts/ledger.mjs review "<이름>" approve|reject
KY 확인             node scripts/apply-reviews.mjs <verified.json>          (dry-run: 쓰기 없음)
반영                node scripts/apply-reviews.mjs <verified.json> --apply   (reviews/brands 에 pending 업로드)
승인                앱 관리자 화면에서 한 건씩 승인 → node scripts/ledger.mjs sync
공지                node scripts/publish-notice.mjs "<제목>" "<본문>" --apply   (승인 완료 후)
```

## Gemini 지시 (시트 규칙)

- 한 번 실행당 최대 10행을 '후보' 탭에 추가하고 멈춘다.
- 열: 식당명 / 지역 / 카테고리 / 안심 등급 / 땅콩 사용 상세 / 출처 유형 / 출처 URL / 원문 인용.
- 원문 인용은 해당 페이지에서 땅콩·견과류·알레르기를 직접 언급한 문장을 한 글자도 바꾸지 않고 복사한다. 요약·합치기·번역 금지.
- 출처 유형 `공식 성분표`는 그 브랜드·식당의 자체 공식 도메인일 때만 쓴다. 블로그·뉴스·위키·정보 집계 사이트는 `언론·블로그`.
- 공식 근거가 없으면 🟢·🔵 등급을 매기지 않는다(🟡 또는 미확인).
- 링크나 인용을 찾지 못하면 그 행은 추가하지 않는다. 한 행에는 브랜드 하나만 적는다.
- 검증 단계는 별도 실행: Q열 `검증 결과`가 빈 행만 열어 반박하는 입장에서 재확인하고 Q(확인/링크 불가/인용 불일치/근거 부족/분리 필요), R(메모), S(확인일), T(검증 후 등급)를 채운다.

## 중복 처리 방지 (처리 장부)

`data/ledger.json`(로컬 상태, git 제외)에 식당마다 키와 지문(URL·인용·등급·설명의 해시)을 기록한다. 지문이 같으면 이미 끝낸 단계는 건너뛴다.

| 단계 | 건너뜀 | 다시 처리 |
|---|---|---|
| 가져오기 | 지문 같음 → `unchanged` | 새 행(`new`), 내용 변경(`changed`) |
| 기계 검증 | 같은 지문으로 통과 후 90일 이내 / 인용 불일치·무관(Gemini 가 행을 고치기 전까지) | 90일 경과, 내용 변경, 접속 실패(최대 3회) |
| Claude 확인(🟢·🔴) | 같은 지문에 결정이 있음 | 내용 변경 |
| 앱 반영 | 같은 지문으로 이미 올림 | 내용 변경 |

- 같은 식당이 여러 탭·행에 있으면 근거(URL+인용)가 있는 행 하나만 쓴다.
- 근거 요건 미달 행은 기계 검증 단계에서 미리 빠지고 보고서(`data/verified/날짜.report.md`)에 사유가 남는다. 그래서 반영 단계가 한 행 때문에 전체가 막히지 않는다.
- `node scripts/ledger.mjs status` 단계별 현황, `pending` 확인 대기 목록, `sync` 관리자 승인 결과 반영.
- 강제로 전부 다시 열려면 `check-sources.mjs ... --force`.

## 기계 검증 (scripts/check-sources.mjs, LLM 토큰 사용 없음)

1. 출처 URL 접속 확인.
2. 원문 인용이 페이지 본문에 그대로 있는지 확인(공백·태그·문장부호 차이 무시).
3. 인용문이 땅콩·견과·알레르기와 관련 있는지 확인(무관하면 근거 불인정).
4. 출처 유형이 `공식`이어도 블로그·위키·뉴스·집계 사이트 도메인이면 `언론·블로그`로 내림.
5. 확신도는 스크립트가 근거 유형에서 정한다(공식 high, 직원 확인 medium, 언론·커뮤니티 low).
6. 등급별 근거 요건(`docs/ops/tier-definitions.md`)을 만족하는 행만 `data/verified/날짜.json`에 남긴다.

한계: 인용이 페이지에 있다는 것과 그 인용이 등급을 뒷받침한다는 것은 다르다. 뒷받침 여부는 Gemini 검증 단계와 Claude 확인(🟢·🔴)이 본다. JS로 그려지는 페이지는 오탐이 날 수 있어 보고서에서 사람이 확인한다.

## Claude 확인 대상

`node scripts/ledger.mjs pending` 에 나오는 🟢(미사용 확인)·🔴(고위험) 통과분. 인용문이 그 등급을 직접 뒷받침하는지, 같은 브랜드의 다른 메뉴·지점 이야기를 일반화하지 않았는지 본다.

## 고정 규칙

- 🟢(low)는 공식 근거 + confidence high일 때만. 블로그·커뮤니티만으로는 🟢 불가.
- 반영은 항상 `pending`. 관리자 승인 없이 사용자에게 노출되지 않는다.
- 영어 필드는 한국어 원문을 그대로 쓴다(번역 오류 방지).
- 공지는 승인이 끝난 뒤에만 발행한다.
- 기존 `safe`·`info` 문서는 근거가 없어 앱에서 "안전(미검증)"·"성분 확인 필요"로 표시한다(`tier-definitions.md` 참고).
