# 안심 등급 정의 (5단계)

월간 조사·검증 에이전트와 앱 라벨의 기준 문서. 값은 코드와 DB에 쓰이는 그대로 적는다.

| 등급 | `risk` | `peanutRiskTier` | 앱 라벨 | 판정 기준 |
|---|---|---|---|---|
| 🟢 | safe | low | 미사용 확인 | 땅콩·땅콩기름 미사용이 공식 성분표 또는 매장 공식 확인으로 증명됨 |
| 🔵 | info | transparent | 성분 투명 | 땅콩 사용 여부와 무관하게, 성분표·직원 설명으로 안전한 주문 경로를 만들 수 있음 |
| 🟡 | caution | medium | 요주의 | 확인을 시도했으나 불명확. 직원이 모른다고 답함, 납품 완제품 소스, 공용 도구 등 |
| 🔴 | danger | high | 고위험 | 안전한 주문 경로가 없음. 땅콩기름 조리, 전 메뉴 포함, 공용 튀김기·소스바 등 |
| ⚪ | unknown | unknown | 미확인 | 근거 데이터 없음. 확인한 적이 없는 상태 |

## 임시 표시 규칙 (기존 문서)

- 기존에 `info` 로 올라간 문서(식당·브랜드)는 근거(출처 URL·원문 인용)가 없어서 앱에서 **"성분 확인 필요"**로 표시한다. "성분 투명"은 위 근거 요건을 통과해 `peanutRiskTier=transparent` 로 올라온 문서에만 쓴다.
- 기존에 `safe` 로 올라간 문서도 같은 이유로 앱에서 **"안전(미검증)"**으로 표시한다. "미사용 확인"은 근거 요건(공식 근거 + confidence high)을 통과해 `peanutRiskTier=low` 로 올라온 문서에만 쓴다.
- 기존 `info`·`safe` 문서를 새 기준으로 재판정하면(🟢/🔵/🟡/⚪) 그때 라벨을 정식 이름으로 되돌린다.
- 구현 메모: 현재는 `risk` 값만으로 라벨을 정하므로, 파이프라인으로 근거를 통과해 올라온 🟢/🔵 문서도 당분간 "안전(미검증)"/"성분 확인 필요"로 보인다(보수적 방향). 항목별로 `peanutRiskTier` 를 보고 정식 라벨을 쓰는 처리는 근거 통과 문서가 실제로 올라온 뒤에 추가한다.

## 경계 규칙

- 🔵와 🔴를 가르는 기준은 땅콩 사용 여부가 아니라 "안전한 주문 경로가 존재하는가"다.
  - 땅콩을 쓰는 메뉴가 있어도 메뉴 단위로 식별·회피 가능하고 표기가 명확하면 🔵.
  - 주방 전체가 땅콩기름이거나 공용 도구로 회피가 불가능하면 🔴.
- 🟡와 ⚪의 차이: 🟡는 확인을 시도했으나 답이 불명확한 경우, ⚪는 확인 자체가 없는 경우.
- 근거가 부족하면 한 단계 위험 쪽으로 분류한다. 🟢 후보인데 근거가 블로그뿐이면 🟡 이하.
- 체인 브랜드는 `brands`, 개별 매장은 `restaurants`에 둔다. 한 행에 여러 브랜드(예: "A / B / C")를 묶지 않는다.

## 등급별 필요 근거 (`scripts/apply-restaurants.mjs` 검증과 동일)

| 등급 | 필요 근거 |
|---|---|
| low | `sourceKind=official`(공식 성분표·매장 공식 확인) + `confidence=high` + 출처 URL + 원문 인용 |
| transparent | `sourceKind`가 official 또는 staff + `confidence`가 medium 이상 + 출처 URL + 원문 인용 |
| medium / high | 출처 URL + 원문 인용 (high는 공식 근거 또는 독립 근거 2건 이상) |
| unknown | 근거 불필요 |
